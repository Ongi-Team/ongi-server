# GitHub 이슈 내용 생성 가이드 (for claude)

## 📌 목적

사용자가 설명한 작업/버그/기능 요청을 분석하여
프로젝트의 GitHub 이슈 템플릿에 맞게 내용을 채워 출력합니다.
(이슈 등록은 사용자가 직접 GitHub에서 합니다.)

---

## 실행 절차

1. 사용자 입력 내용을 분석하여 이슈 유형을 판단합니다.
2. 해당 유형의 템플릿에 내용을 채워 출력합니다.
3. 바로 복사해서 붙여넣을 수 있는 형태로 출력합니다.

---

## 이슈 유형 판단 기준

| 유형 | 기준 |
|------|------|
| **Feature** | 새로운 기능 추가 |
| **Fix / Bug** | 오류, 예외, 잘못된 동작 |
| **Refactor** | 기능 변경 없이 코드 구조 개선 |
| **Chore** | 설정, 의존성, 환경, 문서 |

---

## 유형별 출력 형식

### Feature

```
제목: [Feat] {기능명}

## Issue : ✅ Feature
{작업하고자 하는 기능 설명 — 배경과 목적 중심으로 2~3문장}

## ✅ TODO
{구현해야 할 항목을 실행 가능한 단위로 분리}

1. [ ] task1
2. [ ] task2

## 📎 ETC
{논의가 필요한 사항, 설계 결정, 참고 자료 등. 없으면 생략}
```

### Fix / Bug

```
제목: [Fix] {버그명}

## 1. Issue : 🐞 Fix / Bug
{발생한 문제 상황 설명}

## 2. 원인 파악
1. [ ] {파악한 또는 추정되는 원인}

## 3. 해결 방안
1. [ ] {해결 방법}

## 4. 결과 확인
{수정 후 확인해야 할 항목. 없으면 생략}

## 📎 ETC
{추가 논의 사항. 없으면 생략}
```

### Refactor

```
제목: [Refactor] {대상}

## Issue : ♻️ Refactor
{리팩토링이 필요한 이유}

## Before
{현재 구조의 문제점}

## After
{개선 후 예상 구조}

## ✅ TODO
1. [ ] task1
2. [ ] task2

## 📎 ETC
{추가 논의 사항. 없으면 생략}
```

### Chore

```
제목: [Chore] {작업명}

## Issue : 🧹 Chore
{작업 내용 요약}

## 작업 내용
{수행할 작업을 구체적으로 작성}

## ✅ TODO
1. [ ] task1
2. [ ] task2

## 📎 ETC
{추가 논의 사항. 없으면 생략}
```

---

## 작성 규칙

- **제목** 맨 위에 `제목:` 으로 따로 출력하여 GitHub 이슈 제목 필드에 바로 복사할 수 있게 합니다.
- **TODO 항목**: 사용자가 명시하지 않았더라도 내용을 분석해 자동으로 도출합니다.
- **ETC**: 특별한 설계 결정, 주의사항, 참고 링크가 있으면 채우고, 없으면 섹션을 생략합니다.
- 코드블록(```) 없이 **바로 복사해서 붙여넣을 수 있는 형태**로 출력합니다.
