# GitHub 이슈 생성 가이드 (for claude)

## 📌 목적

사용자가 설명한 작업/버그/기능 요청을 분석하여
프로젝트의 GitHub 이슈 템플릿에 맞게 내용을 채운 뒤,
`gh` CLI를 사용해 GitHub에 직접 이슈를 등록합니다.

---

## 실행 절차

1. 사용자 입력 내용을 분석하여 이슈 유형을 판단합니다.
2. 해당 유형의 템플릿에 내용을 채워 제목과 본문을 준비합니다.
3. 아래 명령어로 GitHub에 직접 이슈를 생성합니다:

```bash
gh issue create --title "제목" --body "$(cat <<'EOF'
본문 내용
EOF
)"
```

4. 생성된 이슈 URL을 사용자에게 출력합니다.

---

## 이슈 유형 판단 기준

| 유형 | 기준 |
|------|------|
| **Feature** | 새로운 기능 추가 |
| **Fix / Bug** | 오류, 예외, 잘못된 동작 |
| **Refactor** | 기능 변경 없이 코드 구조 개선 |
| **Chore** | 설정, 의존성, 환경, 문서 |

---

## 유형별 본문 형식

### Feature

```
제목: [Feat] {기능명}

## Issue : ✅ Feature
{작업하고자 하는 기능 설명 — 배경과 목적 중심으로 2~3문장}

## ✅ TODO
{구현해야 할 항목을 실행 가능한 단위로 분리}

- [ ] task1
- [ ] task2

## 📎 ETC
{논의가 필요한 사항, 설계 결정, 참고 자료 등. 없으면 생략}
```

### Fix / Bug

```
제목: [Fix] {버그명}

## Issue : 🐞 Fix / Bug
{발생한 문제 상황 설명}

## 원인 파악
- [ ] {파악한 또는 추정되는 원인}

## 해결 방안
- [ ] {해결 방법}

## 결과 확인
{수정 후 확인해야 할 항목. 없으면 생략}

## 📎 ETC
{추가 논의 사항. 없으면 생략}
```

### Refactor

```
제목: [Refactor] {대상}

## Issue : ♻️ Refactor
{리팩토링이 필요한 이유}

## Before
{현재 구조의 문제점}

## After
{개선 후 예상 구조}

## ✅ TODO
- [ ] task1
- [ ] task2

## 📎 ETC
{추가 논의 사항. 없으면 생략}
```

### Chore

```
제목: [Chore] {작업명}

## Issue : 🧹 Chore
{작업 내용 요약}

## 작업 내용
{수행할 작업을 구체적으로 작성}

## ✅ TODO
- [ ] task1
- [ ] task2

## 📎 ETC
{추가 논의 사항. 없으면 생략}
```

---

## 작성 규칙

- **TODO 항목**: 사용자가 명시하지 않았더라도 내용을 분석해 자동으로 도출합니다.
- **ETC**: 특별한 설계 결정, 주의사항, 참고 링크가 있으면 채우고, 없으면 섹션을 생략합니다.
- 이슈 생성 전 제목과 본문을 사용자에게 먼저 보여주고 확인을 받은 뒤 `gh issue create`를 실행합니다.
- 생성 완료 후 이슈 URL을 출력합니다.
